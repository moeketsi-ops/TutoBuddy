What a learner session costs, and how we'll measure it

How the simulation works: what goes in, what comes out, what we measure on every model call, which cases we run, and how those numbers add up to the cost and time of a real learner session. This version includes your memory, mastery and pedagogy work, and Grade 12.

Your questionA simulation that takes what the learner sends (text or photo), shows the tokens used and how long a concept takes to explain, so we know what a whole session costs. Plus a feel for the cost, reasoning and memory behind the mastery and pedagogy changes.

The short answer

  • Every model call is measured: tokens in, tokens out, hidden reasoning tokens, the dollars OpenRouter actually billed, and seconds to reply. Your new cost ledger now records the same for live WhatsApp traffic.
  • A session is a chain of those calls. Its cost is the sum. The calculator below adds them up using prompt sizes measured from the code as it is now, memory included.
  • Memory costs little and doesn't grow. With your memory window, a tutoring prompt is about 1,050–1,250 tokens. It stays flat across a conversation, because only the last 2 turns and a summary written by our code are carried.
  • "How long a concept takes" is now measurable. 11 scripted learners walk through 3–4 turn conversations on your memory, mastery and strategy code. We count turns, tokens per turn, seconds, and whether the model judged each attempt correctly.
  • Grade 8 and Grade 12 both run, and results are shown side by side for each grade.
  • Gold "guess" labels are estimates until the first light run with the OpenRouter key replaces them with measured values.

Every tutoring call now returns two things in one response: the reply the learner reads, and a small hidden state record. The record says what the learner did (an attempt that was right, wrong or partial, or a request for the answer), which learning objective it touched, any misconception, and which strategy was used. It adds about 30 output tokens instead of a second model call. Our code, not the model, turns it into mastery scores. Each call also produces a measurement record:

Next: the light simulation

  • Four cheap candidates: Claude Haiku 5.5, DeepSeek V4 Flash, GLM-5.3-Flash and the current Qwen 3.5. Each runs 3 cases per suite for each grade.
  • The runner's quote: about 132 model calls, roughly 13 US cents without the AI judges, or about $4 with them. The judges read every tutoring and practice reply, so they are most of the cost.
  • This is the first time your memory, state record and strategy engine meet a real model. It will show whether models return valid state records and follow the chosen strategy.
  • The tutoring call asks OpenRouter only for hosts that support strict JSON output. A model whose hosts don't support it will show up as an error rather than a reply, which is cheap and useful to find out now.
  • It also checks whether Claude accepts the effort setting through OpenRouter.

Afterwards this page is refreshed with measured numbers in place of the guesses.

Assumptions and limits

  • Visible reply guesses: router 3 tokens, tutor 190 (reply plus state record), practice question 120, marking 60. Vision: about 600 instruction tokens plus 1,200 image tokens.
  • Reasoning guesses per reasoner reply: none 0, low 600, medium 1,500. The router always runs at effort none.
  • In the sessions, follow-up replies to a problem skip the router, as your branch does.
  • Session shapes are illustrative until real WhatsApp traffic exists; your ledger will then give real ones.
  • CAPS note retrieval uses a simple offline matcher that sometimes picks the wrong note. It affects every model the same way, but it weakens grounding.
